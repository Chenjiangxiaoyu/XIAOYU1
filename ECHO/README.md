# ECHO 评论自动采集与分析

## 启动

在项目目录执行：

    python backend/server.py

打开 http://127.0.0.1:8001 。后端同时提供网页和 API，无需另起静态服务。已运行旧版后端时请先重启。可通过 CHAT_PORT 环境变量改端口。

在“我要看反馈”顶部展开“爬虫接口配置”，填写数据源 JSON，点击“启动采集与分析”。

## 链路

爬虫 HTTP 接口 → 游标分页 → SQLite 保存原文和清洗文本 → ID 去重 → DeepSeek 逐条分析 → 校验逐字引用 → 原工作台发现列表与详情。

手动评价同样持久保存并自动分析。页面每 4 秒刷新任务状态。内置示例发现已移除，不会混入真实统计。

## 配置

backend/.env 中沿用 DEEPSEEK_API_KEY 和 DEEPSEEK_MODEL；增加 DOUYIN_COOKIE=实际值（仅本地配置，不提交版本库）。网页只填 cookie_env: DOUYIN_COOKIE，不填写 Cookie 内容。修改已有环境变量或 .env 后请重启服务。

每个视频和产品配置一个 source。示例在网页提供；映射参数包括：
url、method（GET/POST）、params、product、fields、items_path、has_more_path、next_cursor_path、cursor_param。
Cookie 默认放 Cookie 请求头，也支持 X-Douyin-Cookie；如果你的爬虫要求其他方式，拿到文档后调整适配器。
远程接口要求 HTTPS；本地爬虫可用 http://127.0.0.1 。接口地址不得带查询串，查询参数填 params。
配置成功提交后保存在本地数据库，刷新页面会恢复。

每次最多采集 max_pages_per_run 页（1–100），再次启动相同配置可以从断点继续。完成的源不会自动重新扫描新增评论；本版是研究批次，不是定时监控。
“继续分析 / 重试失败”只处理已采集的待分析及失败记录，不继续抓取。
原文存 backend/feedback.sqlite3；页面和模型使用清洗后的文本，默认不展示未脱敏原文。手机号与邮箱脱敏并不等于完整个人信息识别。

## 分析与展示边界

自动分析由现有 DeepSeek 服务完成，需要有效密钥、模型与网络。未配置或调用失败时保留记录，显示失败，可重试，不生成假结果。
每条发现只代表该评论；引文必须在清洗文本逐字出现，否则拒收分析并允许重试。低置信或高影响内容标记待复核。
产品对照表提供已采集、已分析、排除及各情绪条数，不把评论比例当成市场份额或销量。
尚未实现跨评论主题聚类及“领先原因”综合报告；当前链路完成自动入库、逐条分析、产品统计和证据追溯。
原始记录按来源 ID 去重；不同 ID 的相同文本保留。纯表情在本地排除，广告/无关内容由模型进一步标记。

## 恢复和安全

SQLite 保存进度；服务重启后运行中的任务标记中断，可重新启动。单进程内仅一个采集/分析任务。
HTTP 429/部分 5xx 有有限重试，持续失败会停止并保留进度。错误日志不输出 Cookie 或模型密钥。
仅监听本机 127.0.0.1，请不要直接暴露到公网。第三方页面的跨域写入会被拒绝。
/api/comments/import 支持外部模块逐条投递，按 external_id 去重；成功确认代表接收持久化，不代表分析完成。

## 测试

    python -m unittest discover -s backend -p "test_*.py" -v

自动测试使用模拟模型/本地接口，不消耗真实模型额度。覆盖 API、持久化、重复提交、错误引用拒收、模型失败重试、采集分页与 Cookie 隔离。
真实爬虫接口和真实 DeepSeek 返回仍需联调；尚未完成浏览器视觉检查。
