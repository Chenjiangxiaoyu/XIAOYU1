# Feedback Ingest Skill：原型与改进路线

## 1. Skill 定位

`feedback-ingest` 是反馈系统的入口清洗流程：接收用户自由文本、表单或批量导入评价，生成可供下游分析的脱敏、可追溯记录。它不要求用户先选星级、产品或情绪类别，也不把评论改写成单一情绪。

职责边界：
- 本 Skill：输入校验、PII 识别与脱敏、文本副本规范化、标签保留、质量标记、重复候选检测、结构化交接。
- Entity Resolver：识别标签类型并匹配产品/主题实体。
- Aspect Sentiment：识别一段话中多个方面的正负情绪。
- Feedback Search：按老板的产品/问题标签检索评价。
- Insights：聚合、给建议和评估风险。

Skill 描述处理规则；后台代码负责真正的数据存储、访问权限、加密、删除、速率限制和 API 参数校验。

## 2. 原型处理流程

```text
评论输入 / 文件导入
  → 校验来源字段、编码和格式
  → 建立稳定 feedback_id 与来源记录
  → 在受控环境识别并遮蔽 PII
  → 保留分析文本，同时生成匹配专用规范化副本
  → 解析并保留 #标签原文、跨度和异常提示
  → 标记质量问题
  → 区分重复导入、相同内容、近重复候选
  → 输出结构化记录
  → 交给实体归一、情感分析、搜索和报告流程
```

## 3. 原型输出

关键字段包括：

- `feedback_id`、可信来源 ID、渠道、批次和清洗版本。
- `raw_text_ref`：受限原文存储引用；不是权限控制本身。
- `analysis_text`：脱敏后保留原始表达特征，用于方面级情感分析。
- `matching_text`：只供精确/近重复匹配的规范化副本。
- `offset_map_version`：在脱敏和规范化改变文本长度后，将跨度映射回原文。
- `tag_mentions`：标签原文、来源、原文/分析文本跨度、解析状态和警告。
- `pii_redactions`：类型、跨度、检测方法和置信信息。
- `quality`：状态、原因代码、证据跨度。
- `duplicate`：重复导入状态、内容组、候选记录、相似度和复核状态。

近重复分组不代表自动删掉或合并。报告统计时区分重复导入事件、相同文本的独立用户提交和经明确规则确认的分析分母。

## 4. 这版相较初稿改进了哪里

1. **补足数据安全边界**：明确原文与分析副本分离、最小化下游传输、限制原文访问、日志不记录原文/PII，并指出 Skill 文本本身不能替代后台安全实现。
2. **隔离恶意指令**：评论、标签、文件文本和模型输出一律视为不可信数据；评论里的“忽略规则”、链接或工具请求只作为内容，不执行。
3. **强化 PII 处理**：覆盖账号、地址、证件、支付、精确位置和凭证等；增加低置信复核、中文识别评估、外部模型传输前脱敏和失败隔离。
4. **保护用户原意**：保留否定、转折、emoji、粗口、重复标点、错字、网络表达和中英文混写；把分析文本与匹配文本拆开。
5. **修正跨度风险**：脱敏会改变文本长度，因此新增原文与副本的跨度映射约定，并统一索引单位和区间格式。
6. **完善标签规则**：遵循无空格 `#标签` 语法，保存跨度和解析警告，不自动拼接或改写标签。
7. **细分重复类型**：来源 ID 负责幂等识别；相同文本但来自不同用户仍是独立反馈；相似度只召回候选，需复核。
8. **防止过度过滤**：疑似垃圾、广告、机器人只作为质量标记；激烈情绪或粗口不应因此降权或排除。
9. **固定输出和评估方向**：给出 JSON 字段、状态枚举建议，以及 PII 误遮蔽/漏检、标签跨度、重复候选准确率和评论情绪保留等指标。

## 5. 借鉴的 GitHub 开源项目

- [Presidio](https://github.com/data-privacy-stack/presidio)：PII recognizer/anonymizer 框架，参考规则、NER、上下文和自定义识别器的分层架构。中文需要定制和本地评估。
- [OpenAI Privacy Filter](https://github.com/openai/privacy-filter)：可本地运行/微调的 token 分类 PII span 检测器，值得评估为非结构化 PII 的一层检测器。仓库声明语言以英语为主、仅做有限的多语言鲁棒性评估，因此不能直接视为中文生产可用，也不能单独依赖；应和规则/校验器组合并实测误遮蔽率。
- [datasketch](https://github.com/ekzhu/datasketch)：MinHash + LSH 大规模近重复候选召回。它是近似算法，适合筛候选，不负责最终合并判定；小规模 MVP 可先用 ID、精确指纹和字符 n-gram。
- [RapidFuzz](https://github.com/rapidfuzz/RapidFuzz)：Levenshtein 等字符串相似度，适合候选二次复核。相似分数不是“同一提交”的证据。
- [dedupe](https://github.com/dedupeio/dedupe)：基于人工标注匹配对学习结构化记录链接规则，可借鉴人审结果迭代匹配器；其目标更偏字段/记录链接，不是评论近重复的直接替代品。
- [OWASP Prompt Injection Prevention Cheat Sheet](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.md)：参考把不可信文本与指令分离、限制工具权限、在应用层验证操作的原则。

项目只是算法/架构参考，不代表已选型或已集成。使用前需核对许可证、维护和部署要求；所有候选都需要在本项目的中文、真实风格评估集上验证，尤其关注个人信息漏检、产品名误遮蔽和不同用户反馈被误合并。
## 6. 未来可能需要改进的地方

### 数据和安全
- 明确各来源的原文保留期限、删除请求流程、授权角色及加密/密钥管理方式。
- 扩展敏感数据分类和各语言/地区的 recognizer；针对中文姓名、地址、账号、证件和口语化个人信息建立评估集。
- 评估脱敏对下游情感识别的影响，并验证所有第三方模型、错误追踪和分析工具都只收到允许的数据。
- 设计附件、截图、语音转写等多模态输入的单独扫描流程；当前原型主要处理文本。

### 算法和质量
- 用真实数据校准 PII 置信度、低信息量判断和近重复阈值；不要直接套用开源默认阈值。
- 为中文重复检测比较字符 n-gram、编辑距离、MinHash/LSH 和语义向量召回在不同渠道、短评和模板内容上的效果。
- 加入跨渠道重复导入的来源 ID 映射、模板活动检测、同用户重复提交政策，并防止协调刷评被错误计为自然热度。
- 建立持续回归集和线上漂移监测，按语言、渠道、PII 类型和用户输入设备统计错误。
- 评估手工抽查和用户纠错入口，将确认结果纳入别名/质量规则更新，但不自动改写历史记录。

### 产品和系统集成
- 将 JSON 示例冻结为严格 JSON Schema/TypeScript 类型，并由服务端校验。
- 将审核队列、重复候选查看、误脱敏恢复（仅授权者）、目录版本和重跑流程接入后台管理界面。
- 定义隐私异常、解析失败、超时和下游不可用时的重试、隔离、告警和回滚策略。
- 与 Entity Resolver、Aspect Sentiment、Feedback Search、Insights 建立版本化接口，避免字段语义漂移。

## 7. 目前尚未实现的范围

当前交付是 Skill 指令原型，不是可部署的清洗服务。它没有连接数据库、识别器、去重索引或审核后台；也没有实际运行中文 PII/近重复基准。需要先用小规模、经授权并已脱敏的数据建立评估集，再决定部署哪个库、算法和阈值。
