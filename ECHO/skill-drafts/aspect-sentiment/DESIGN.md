# Aspect Sentiment Skill：原型与改进路线

## 1. 定位

本 Skill 负责分析单条评价内部的多方面情绪。它把一段文字转成若干条“方面/对象—观点证据—极性—强度”记录，允许同一用户一边夸一个功能、一边骂另一个功能。它不负责整条评价的单一好坏分类、产品别名归一、评论检索或产品路线图决策。

## 2. 原型处理流程

```text
脱敏后的评价文本 + Entity Resolver 的实体/主题目标
  → 切分独立评价主张
  → 抽取显式/隐式方面与观点跨度
  → 将方面和观点配对
  → 关联正确的产品实体/跨实体关系
  → 对每对独立判极性
  → 单独估计强度/可选情绪类别
  → 保留证据、跨度、置信状态和复核标记
  → 输出每方面记录；整条 mixed 只由方面记录派生
```

原型示例：

> `#iPhone18 电池太顶了，出门一天还有电；但相机夜景糊得离谱，气死我了。`

应至少拆出电池的正向评价与相机夜景的负向评价。不能把整条评论粗略判为“混合”后丢失每项具体信号；也不能把两种情绪折成一个平均分。

## 3. 当前 Skill 草稿的设计内容

- 明确允许一条评价多个极性并存，不要求星级或单一情绪标签。
- 以方面—观点—极性三元组/评价单元为核心，保留原文证据跨度。
- 显式处理否定、转折、程度词、反讽、emoji、重复标点、中英文混写和隐式方面。
- 将极性、强度、情绪类别分开；情绪强度不代表产品问题严重程度。
- 使用 Entity Resolver 的目标实体和关系，但要求正文证据支持目标绑定；不因多个标签共现就认定所有标签都是评价对象。
- 为低置信、隐式方面、反讽等不确定情况保留复核状态；区分模型分数和校准概率。
- 定义跨度、下游隐私和评估约束，防止输出没有原文依据的解释。

## 4. GitHub 开源项目和数据集借鉴

### PyABSA：首选 ABSA 工具箱 baseline

[PyABSA](https://github.com/yangheng95/PyABSA) 覆盖方面词抽取、方面极性分类、方面情绪三元组抽取（aspect, opinion, sentiment）以及更丰富的方面类别/观点/情绪任务；提供训练、推理、数据集格式、评估和人工标注辅助。可借鉴任务拆分、标注格式和 baseline 评测流程。仓库许可为 MIT；使用时仍需核对具体 checkpoint、模型权重和数据集各自的许可与性能。

### ASAP：中文人工标注方面情绪数据

[Meituan-Dianping/asap](https://github.com/Meituan-Dianping/asap) 提供中文餐饮评论及预定义方面类别（如食物、服务、环境）的人工极性标签，适合验证“同一评论多个方面各自打分”和构建中文方面分类 baseline。它的领域是餐饮、方面类别固定，不能代表任意产品/软件；用于本产品时应借鉴方法和格式，不直接当作通用训练真值。

### Chinese ASTE 弱监督资源

[chn_review_aste](https://github.com/chiawen0104/chn_review_aste) 展示通过迭代弱监督构建中文评论方面情绪三元组数据集的方案，并提供小规模人工金标子集。可借鉴低成本扩数据和保留 gold set 验证的流程。其来源集中于 Google Maps 餐饮评价，且大部分标签为模型/规则生成，不能把弱标注直接当作真实标签；需要检查数据/模型许可，并用独立人工样本评估。

### 适用选型

先用 PyABSA 及其合适的 multilingual/中文 checkpoint 做 baseline；如果效果不足，再比较 span-based/joint ASTE 和结构化 LLM 抽取。中文餐饮数据只用于流程预检，产品的设备、软件、服务等领域需建立自己的小型人工金标集。

## 5. 相对初稿补上的改进

若初稿只是“判断好评/差评并统计”，这版补全了对实际反馈业务必要的细节：

1. 从整段极性改为多个方面级评价单元，避免混合情绪互相抵消。
2. 为每种极性保存观点跨度、方面、目标实体和证据来源，支持审核和老板报告溯源。
3. 将标签提及与评价目标分离；关联目标需有正文依据，并继承 Entity Resolver 的关系。
4. 将极性、情绪类别、强度和严重程度分开，不让一个分数包办含义不同的判断。
5. 专门处理否定、转折、讽刺、隐式方面、引用和 emoji 等容易导致极性翻转的语境。
6. 允许中立、未提及、不确定和待复核，避免把“没提到”当中性或强行猜测。
7. 定义证据跨度、置信字段和评估指标，并使用中文方面情绪开源资源做 baseline 参照。

## 6. 未来可能需要改进的地方

### 模型效果和样本
- 建立覆盖硬件、软件、服务、订阅和跨实体兼容问题的本域人工金标集。
- 加入激情口语、网络梗、反讽、输入错误、口语省略、多方面同段混合极性等难例。
- 比较 PyABSA multilingual checkpoints、专用中文模型、span-based ASTE 和结构化 LLM 抽取在速度/成本/准确率/可解释性上的表现。
- 从人工复核样本迭代训练集，但保持独立、固定、按产品/实体留出的测试集。

### 标签体系与输出
- 定义领域方面 taxonomy：通用方面、产品类专属方面和用户自由表达之间的层级映射；未知方面可以提议新主题但不能自动改变全局 taxonomy。
- 完成正式 JSON Schema，标清 `not_mentioned`、`neutral`、`mixed`、`uncertain` 的互斥关系和单位。
- 校准置信度/强度分数；上线前不把 raw logits/model scores 展示为准确概率。
- 评估极性之外是否需要情绪类别，以及它对产品决策的实际帮助。

### 产品集成与决策
- 将低置信单元接入人工复核界面，允许快速修正方面、对象、观点跨度和极性。
- 汇总到产品报告前统一统计口径：按独立用户/提交/去重策略统计，不能因同一用户多次重复表达放大比例。
- 和风险建议 Skill 区分：情绪强度是文本信号，问题严重度还需结合影响面、频次、故障数据和业务规则。
- 加入版本监测、漂移告警、错误案例回流，以及模型/词典更新回滚机制。

## 7. 当前边界

当前产物是 Skill 和原型设计说明，不是已训练模型或运行服务。Skill 不会自行装载 PyABSA、下载 checkpoint、创建标注数据、访问评价库或保证模型准确率。数据集使用与商用部署前要核对数据许可和来源适用性；实际选型需要先建本域评估集。
