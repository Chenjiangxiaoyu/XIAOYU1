# Feedback Search

## 职责与前置条件
调用时接收老板原始查询、当前实体/主题目录版本、身份与租户范围、授权检索接口及时间/渠道/版本过滤条件。没有可用检索接口时只返回规范化查询计划；不得声称查到了评价。只检索当前操作者有权访问的反馈。

本 Skill 负责查询解析、范围解释、检索与溯源，不负责推断情绪或生成建议。输出交由 `feedback-insights`。

## 查询流程
1. 保存原始查询及跨度；按 `#连续无空格` 解析标签，同时保留普通关键词。空格结束标签，格式颜色不代表是否已映射。
2. 每个词分别分类为实体、方面、问题、场景或未确定。按目录版本查询对应实体/主题目录和确认别名；未知项不得由模型记忆补全。
3. 构建显式 query plan：解析项、匹配 ID、匹配路径、范围、未解析项、过滤器和 OR/AND 逻辑。多标签默认 OR（任一条件命中）；只有用户明确要求“同时满足”才用 AND，并在结果中显示。
4. 控制实体范围：
   - 别名只映射到确认后的同一 ID。
   - 系列查询可按目录包含已确认子型号，结果注明 `hierarchy_expansion`；具体型号默认精确，不扩展到兄弟型号或整系列。
   - 公司、品牌、产品、系统、应用之间的相关关系不是别名。默认不自动并入；老板显式启用相关实体时，标明扩展规则并分组呈现。
   - 方面/问题按同义词精确映射；主题层级扩展必须可见且可关闭。
5. 将解析条件与租户/ACL、日期、渠道、版本过滤器一并传给授权检索接口。权限过滤必须在结果暴露前执行。
6. 未解析词仍可对原始标签字段做精确检索，独立标记 `unresolved_exact`。部分解析时可返回已解析范围，但显著标出覆盖不完整；不能把空结果解释成无用户反馈。
7. 对反馈 ID 去重，分别报告命中条目和唯一反馈数。重复/转载记录可保留组关系，不可悄悄丢失。
8. 为每条结果保留命中反馈 ID、标签原文、匹配路径、目录版本、索引版本和过滤器；返回中不暴露 PII。
9. 把去重后的原始反馈 ID、分析文本、情感/实体结构、匹配元数据和数据质量标记传递给 `feedback-insights`。

## 离线优先与联网
当前以本地目录和反馈库运行，不调用互联网。若将来显式配置联网目录查询，只能生成未知项候选及来源、时间，不能修改现有目录或跳过审核。联网失败时继续本地检索并标明未联网查证。

## 输出契约
至少返回：`query_id`、租户/权限过滤状态、原始与归一查询、实体/主题 ID、匹配方式、扩展范围、OR/AND、时间/渠道/版本过滤器、命中数/去重数、未解析/歧义项、权限/数据源/索引告警、目录和索引版本、结果反馈 ID 及溯源元数据。PII 不进入老板端结果。

## 评估
用标注查询集检查：标签分类/链接准确率；召回率、误召回率；具体型号误扩展率；系列子型号漏召回率；原始未解析标签命中率；OR/AND 正确率；ACL 越权暴露数（必须为 0）；重复计数差异；端到端完整率、延迟及空结果诊断准确性。按实体类型、匹配路径和语言分别报告。
