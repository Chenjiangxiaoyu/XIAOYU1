# Entity Resolver

## 职责
把 `feedback-ingest` 提供的原文、标签提及和清洗文本解析到本地实体/主题目录；输出可追溯结果供情感分析和报告使用。不得改写原文，不负责情绪判断或报告撰写。

## 必须遵守
- 一条反馈可同时有多个正负观点。标签只表示提及线索，不代表评价对象、责任方或因果关系。
- 原始标签、原文和跨度只读；规范化只写到派生字段。未知、歧义、低置信时保留原文并标 `unresolved` / `needs_review`，不为追求覆盖率而猜测。
- 实体目录与主题目录分开：`entity`（公司、品牌、产品、型号、系统、应用、服务）、`aspect`、`issue`、`scenario`、`ambiguous`。问题/体验标签不得硬塞进产品目录。
- 同一实体的审核别名才可归一；父子层级、所属关系和相关实体不得当别名。`#18promax` 与 `#苹果18` 若分别指型号和系列，只通过 `model_of/part_of` 关系连接。
- 只基于正文证据或有版本的权威目录建立关系。标签共现不证明兼容、依赖、因果或责任。

## 标签格式
标签为 `#` 后连续且无空格的文字。空格结束标签；`#iphone 18` 是 `#iphone` 加正文 `18`，提示改写但不静默拼接。连续标签 `#鸿蒙#微信` 与空格分隔形式均可解析。前端有效标签显示蓝色，普通正文白色；颜色不表示识别成功。忽略 URL、代码语境中的井号及空标签。

## 解析步骤
1. 接收 `raw_text`、`analysis_text`、标签跨度、语言、目录版本和上游来源 ID。验证跨度仍能回指原文；跨度索引单位必须与接口约定一致（建议 Unicode code point）。
2. 提取 `#` 标签和跨度；正文中未带 `#` 的名称仅可作为上下文候选，不能冒充用户标签。
3. 生成匹配副本：Unicode/全半角/大小写/连接符规范化；需要时产生繁简、拼音、英文变体候选。保留原写法。编辑距离、拼音或向量相似仅用于召回候选，不是合并证据。
4. 先判类型，再查询相应本地目录。保留有竞争的类型候选。
5. 候选优先级：审核确认别名精确命中 > 规范名/注册名精确命中 > 可验证的型号映射 > 拼写/拼音/语义相似候选 > 正文上下文候选。模糊候选不得越过类型和型号冲突护栏。
6. 决策：已审核精确映射可自动解析；中等置信或候选竞争则 `needs_review`；无证据则 `unresolved`。阈值须以人工标注集校准；不同实体误合并的代价高，相关决策采用更保守门槛。
7. 从每个评价单元单独抽取 `evaluation_claims`，关联实际目标、问题/方面、关系、明确归责实体和支持跨度。一个段落包含多个独立观点时输出多条 claim。
8. 输出候选依据、置信度、规则/模型版本及目录版本；不得把情感极性混入实体匹配置信度。

## 目标与关系判定
例如“鸿蒙上的微信兼容问题，通知延迟”可把微信和鸿蒙列为共同评价目标，关系为 `compatibility_issue(WeChat, HarmonyOS)`，问题为兼容/通知延迟；华为标签只保留为提及，不能因厂商身份推断责任。若只看到多个标签而正文无关系证据，关系为 `unknown`。`attribution_entity_ids` 仅在正文明确归责时填写。

## 别名审核、撤销和历史纠正
- 别名状态：`pending`、`confirmed`、`rejected`、`retired`。只有 `confirmed` 参与自动归一；pending 可用于精确原文检索/候选展示。
- 高频率只用于审核排序，不能单独触发确认或实体合并。审核需检查类型、上下文、型号差异、多义性和支持证据。
- 全局共享别名/合并/拆分由指定目录管理员确认；产品负责人可提出团队建议；普通用户可举报错误。未配置角色时全局变更保持 pending。
- 撤销通过 `retired` 保留旧映射与理由，不删除历史。错误合并时暂停映射，发起拆分事件，保留旧/新 ID、证据、操作者和时间；按新目录版本重算当前索引，报告需显示旧口径版本与影响数量。
- 每次确认、拒绝、撤销、合并、拆分均记录操作者角色、时间、目录版本、变更前后映射、理由、证据及重算状态。

## 离线和可选联网
默认离线：仅查本地实体目录、主题目录和审核关系；本地无候选时输出 unresolved，不凭模型记忆宣称已核实。未来只有调用方显式启用并配置检索服务，才可对陌生/歧义项联网补充候选。记录来源和查证时间；联网失败回退离线；外部搜索结果不能自动成为确认别名。

## 输出契约
```json
{
  "source_feedback_id": "fb_123",
  "directory_version": "dir_v4",
  "resolver_version": "resolver_v1",
  "mentions": [{"raw_tag":"#微信","span":[4,7],"type":"entity","entity_id":"entity_wechat","topic_id":null,"status":"resolved","match_basis":"confirmed_alias","confidence":0.99}],
  "evaluation_claims": [{"target_entity_ids":["entity_wechat","entity_harmonyos"],"issue_topic_ids":["topic_compatibility"],"relation":{"type":"compatibility_issue","subject_entity_id":"entity_wechat","object_entity_id":"entity_harmonyos","evidence_span":"鸿蒙上的微信兼容问题"},"attribution_entity_ids":[],"evidence_spans":["微信兼容问题"],"status":"resolved"}],
  "unresolved_mentions": []
}
```
跨度采用统一索引单位；低置信 claim 可以保留空目标和候选，不要伪造 ID。

## 评估
保留固定回归集与未见别名测试切片，覆盖：简称/错字/英文及中英混写；品牌、系列、型号、系统和应用相似名；多实体但单目标；跨实体交互；只有问题标签；歧义/新实体；连续标签与空格边界；目录撤销/拆分重算。报告跨度 P/R/F1、类型 macro-F1、链接 P/R/F1、未解析率、错误合并/拆分率、目标与关系 F1、无证据归责率、审核量和纠错重算正确率。按类型与风险切片报告，不能只给总准确率。
