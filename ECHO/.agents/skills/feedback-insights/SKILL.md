# Feedback Insights

## 目标
把分散的用户声音转成可追溯的产品决策依据。区分用户事实、分析推断和建议；不把情绪强度当作影响规模，也不因单条好评/差评就下总体结论。

## 输入
尽量收集：产品/版本、评价原文、提交时间、渠道、用户类型或场景、评分（若有）、地区/语言。缺失字段标为未知，不自行补造。定义分析时间窗和目标问题；若用户未指定，说明使用的时间范围。

## 工作流
1. **准备与隐私**：保留原始数据只读副本；剔除空白、广告/无关内容、乱码。识别并遮蔽邮箱、电话、姓名、订单号等个人信息；报告中不暴露可识别内容。
2. **规范化**：统一编码、空白、日期、评分尺度和语言；保留原文及清洗后文本的映射。翻译只用于分析，引用时标记为译文。
3. **去重与质量标记**：用规范化文本、来源ID和时间窗口查找完全/近似重复；标记疑似刷评、机器人、极短或低信息量内容。不要静默删除：报告数量、规则和影响，并分别计算原始条数与去重后样本量。
4. **分类**：逐条标记正向/中性/负向/混合情绪、主题（如易用性、性能、价格、可靠性、支持）、场景、严重程度及置信度。允许多主题和混合情绪；低置信样本进入待复核，不强行归类。
5. **汇总**：按主题、情绪、时间、渠道和用户场景汇总数量与占比。展示分母、样本规模和时间窗；有可比基线时再讨论趋势。避免把自选择评价样本说成全体用户代表。
6. **发现**：提炼重复痛点、关键正向价值、未满足需求和异常信号。每个发现附支持它的样本数/占比、代表性匿名摘录和置信度；指出相互矛盾的证据。
7. **建议与排序**：每条建议说明目标用户、要改变的体验、预期效果、实现方向、验证指标和优先级。好评对应“保护并扩大有效价值”的实验，例如扩大可发现性、适用场景或容量，而不是无依据地扩张；差评对应问题缓解与根因验证。区分快速修复、探索实验和长期投入。
8. **风险评估**：对每项建议列出发生可能性、影响、证据置信度、受影响对象、缓解措施、监测指标和回滚条件。考虑回归/稳定性、可访问性、公平性、隐私安全、成本/复杂度、误伤现有用户及指标被操纵。用明确等级（低/中/高）并写出判定理由；高影响低置信建议先实验。
9. **行动计划**：给出近期/后续/暂缓事项、负责人角色建议、验证周期和决策门槛。建议通过A/B或可逆试点验证，不把相关性表述为因果。

## 输出格式
- 一页摘要：分析窗口、去重后样本量、情绪概览、最重要的3项发现。
- 数据质量：原始/去重/排除数量，清洗规则和局限。
- 用户声音：主题分布、正向价值、主要痛点、趋势与匿名证据。
- 建议清单：优先级、依据、预期收益、验证指标。
- 风险矩阵：可能性、影响、置信度、缓解、监控与回滚。
- 行动路线图：下一步、负责人角色、时间建议。
- 附录：分类口径、假设、未知项和需要人工复核的内容。

## 质量门槛
- 所有百分比注明分母；小样本注明“方向性信号”。
- 不编造评论、基线、用户属性、统计显著性或业务收益。
- 引用匿名且可追溯到样本ID；不输出PII。
- 区分观察、解释和推荐；给出不确定性及反例。
- 涉及安全、健康、财务、歧视或隐私的高影响内容，标记人工复核。
- 若样本不足以支撑结论，明确说“证据不足”，提供下一步采样建议。
