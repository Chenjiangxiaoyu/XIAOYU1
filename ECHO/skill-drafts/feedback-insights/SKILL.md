# Feedback Insights

## 职责
将 `feedback-search` 输出的授权反馈样本、数据质量信息、实体/主题映射和方面情绪标注转成有证据的发现。改进方案交给 `improvement-planner`；风险评估交给 `change-risk-assessor`；成功标准交给 `success-criteria`。输入不足时说明缺口，不用建议性语言掩盖证据不足。

## 工作流程
1. 核对分析对象、时间窗、数据源、版本、目录版本、权限范围、去重口径和可分析分母。缺失即标记未知。
2. 报告原始、去重、排除、待复核和最终样本数。重复、低信息量、疑似无关内容可以标记，但不可静默移除；引用需脱敏。
3. 以评价单元和方面证据为基础，分别归纳主要问题、正向价值、混合/矛盾体验、未知项。单条长评可同时含好坏观点；情绪强度不代表影响范围。
4. 按方面、用户群、场景、渠道、版本和时间窗分层；每个定量发现提供分子/分母、样本数、证据 ID 和匿名摘录。说明不同群体间样本量是否可比。
5. 只有同口径、可比窗口且有基线时才描述趋势。不能把自选择反馈说成全部用户的代表，也不能把相关性说成因果。
6. 每项发现按结构输出：观察事实、支持证据、反例/冲突、范围、置信度、限制。没有足够证据就明确标“证据不足”。不提供解决方案或风险判断。

## 输出
- 范围与口径：对象、时间、来源、分母、去重规则及版本。
- 数据质量与限制：缺失、偏差、未解析标签、待复核数据。
- 发现清单：`finding_id`、类型（pain/value/mixed/unknown）、主题、受影响群体、计数/分母、证据反馈 ID、匿名证据跨度、反例、置信度和限制。
- 用户群差异：只比较样本量与口径可比的群体；否则说明不可比。
- 交接：将发现及其证据包交给 improvement-planner；不替下游 Skill 预设结论。

## 质量检查
不编造反馈、样本、基线、人口属性或业务影响；不将提及频率当作严重度；不将标签共现当作评价对象；不以整体正负情绪抵消方面差异；所有百分比给出分母，所有引用匿名并能追溯。
