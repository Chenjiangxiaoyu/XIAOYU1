# Feedback Search — 原型与优化记录

## 原型
老板在产品工作台输入一个或多个 `#` 标签/关键词后，按本地目录把查询拆为实体、方面、问题、场景；依审核别名和明确层级扩展查询；再调用授权反馈检索接口，返回去重前后数、过滤条件、匹配路径和目录版本，并把证据记录交给 `feedback-insights`。

## 相较初稿的优化
- 将查询分类与实体链接分开，问题标签不再被当作产品名。
- 定义多标签默认 OR，并支持明确要求的 AND；在界面显示逻辑。
- 把系列向下展开与具体型号精确搜索区分，避免扩大到兄弟型号。
- 关联实体仅在用户明确扩展或记录本身有关系证据时纳入；不把关联关系视作别名。
- 未解析标签仍可按原始标签检索，并明确结果不完整；缺数据源时只返回查询计划。
- 输出来源、过滤、去重口径、目录与索引版本，避免报告不可复现。
- 默认离线优先；未来联网仅可用于可选目录补充，不影响本地运行。

## GitHub 项目借鉴与边界
- [Meilisearch](https://github.com/meilisearch/meilisearch)：可自托管的全文搜索、过滤、分面和 typo tolerance，可作为反馈文本/标签的召回索引。借鉴“精确匹配优先、模糊命中透明排序、按字段关闭错字容忍”的思路；短标签/数字型号应禁用或严格限制模糊匹配。它只负责召回，不负责决定两个产品是否同一实体，也不替代授权/隐私过滤。
- [Meilisearch typo tolerance 文档](https://github.com/meilisearch/documentation/blob/main/resources/internals/typo_tolerance.mdx)：说明错字容忍按词长配置且是排序信号；因此候选匹配要显示路径并避免模糊结果悄悄扩大查询范围。
- 产品 MVP 可以先用数据库精确 ID、目录别名、时间/渠道过滤；只有数据量或全文检索需要时再加搜索引擎。引擎自托管仍要管理服务和索引，不等于零运维。

## 后续改进
实现租户隔离与权限行过滤；支持保存查询、报告快照、游标分页和增量索引；做查询解释 UI、目录纠错反馈；有标注数据后评估召回/误召回及语言切片；可选加入语义召回，但需独立阈值、证据展示和离线回退。联网产品目录仍须管理员确认。
